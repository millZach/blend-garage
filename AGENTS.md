# Blend Garage — Agent & Developer Guide

Blend Garage is a web-first 3D car garage and future physics/open-world platform built with **TypeScript + Three.js** (pure TS 3D core + thin React/Tailwind HUD) and an automated **Blender CLI `.blend` import pipeline**.

## Architecture Boundaries

- `cars/incoming/` — Drop `.blend` car files here.
- `apps/garage-web/public/cars/` — Auto-generated runtime Car Packages (`manifest.json` + `<car-id>/model.glb` + `<car-id>/vehicle.json`). Generated by `npm run import-cars`.
- `tools/car-importer/` — Headless Blender CLI exporter (`export_car.py`) + Node CLI runner/watcher (`import-cars.mjs`).
- `packages/vehicle-core/` — Shared TypeScript schemas (`VehicleManifest`, `CarBuild`, `PaintConfig`, `PartSlot`), paint presets, build validation, and Three.js material/part binding helpers.
- `packages/damage-bridge/` — **Phase 2 boundary** for the external JS/TS/WASM car damage physics simulation (`DamageSimulator` interface + typed-array mesh deformation contract).
- `packages/world-racing/` — **Phase 3 boundary** for open-world driving, suspension, and racing add-ons.
- `apps/garage-web/` — Phase 1 Interactive Garage app:
  - `src/engine/` — Pure TypeScript Three.js engine (scene, lighting, bays, camera rigs, car rig loader, paint & part mutators). Keep React completely out of `src/engine/`.
  - `src/ui/` — Thin React + Tailwind HUD overlay subscribing to engine state snapshots.

## Key Commands

```bash
npm install            # Install all workspace dependencies
npm run import-cars    # Convert all .blend files in cars/incoming/ into runtime Car Packages
npm run watch-cars     # Watch cars/incoming/ and auto-import whenever a .blend file is added/saved
npm run validate-cars  # Validate existing Car Packages in apps/garage-web/public/cars/
npm run dev            # Start Vite dev server for the Interactive Garage
npm run typecheck      # Typecheck every workspace package and app
npm run test           # Run Vitest test suite
npm run build          # Production build of all packages + web app
```

## Blender `.blend` Naming Conventions (Optional — Graceful Fallback Supported)

Any `.blend` dropped into `cars/incoming/` will import and appear in the garage immediately, even with zero tagging. Using these optional naming conventions automatically unlocks interactive features:

- **Wheels:** Objects named `wheel_FL`, `wheel_FR`, `wheel_RL`, `wheel_RR` (or containing `wheel` + `fl`/`fr`/`rl`/`rr`) are recognized as wheel assemblies for spinning/steering/swapping.
- **Swappable Parts:** Objects prefixed with `part_` (e.g. `part_spoiler`, `part_hood`, `part_bumper_front`, `part_bumper_rear`, `part_exhaust`, `part_roof_rack`, `part_door_FL`) become toggleable/swappable parts in the garage UI.
- **Mount Slots:** Empties prefixed with `slot_` (e.g. `slot_spoiler`, `slot_roof`, `slot_exhaust`) mark anchor points where universal aftermarket parts snap onto any car.
- **Paint & Material Zones:** Materials matching these prefixes/keywords auto-bind to the Paint Booth:
  - `mat_paint_primary` / `paint` / `body_paint` → Primary Body Paint
  - `mat_paint_secondary` / `secondary` → Secondary / Two-Tone Paint
  - `mat_paint_accent` / `caliper` / `accent` → Accent / Trim Paint
  - `mat_rim` / `rim` / `alloy` → Wheel Rim Finish
  - `mat_glass` / `window` / `windshield` → Glass Tint
  - `mat_headlight` / `mat_taillight` → Emissive Lights

## Coding Conventions

1. Keep 3D rendering, asset loading, cameras, and future physics loops inside `src/engine/` and `packages/*` as pure TypeScript with zero React imports.
2. All serialized car manifests and custom builds must stay plain JSON validated against `packages/vehicle-core`.
3. Never hardcode absolute paths to Blender; `tools/car-importer/import-cars.mjs` checks `BLENDER_PATH`, PATH, and standard OS install directories automatically.
